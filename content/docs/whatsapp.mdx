## Modes disponibles

MailPulse supporte deux modes côté organisation :

- Meta Cloud API, recommandé pour la production.
- WhatsApp Web via Evolution API et Baileys, pratique pour démarrer ou dépanner.

## Meta Cloud API

Meta est le canal officiel. Il nécessite un WhatsApp Business Account, un numéro, un token, un `phone_number_id` et des templates approuvés pour les messages hors fenêtre de 24h.

## Baileys et Evolution API

Le mode QR code connecte une session WhatsApp Web. Il est simple, mais non officiel. La session peut se déconnecter, et un usage en volume peut exposer le numéro à des restrictions ou suspensions.

## Ressource MailPulse

Si `MAILPULSE_MANAGED_WHATSAPP_ENABLED=true`, MailPulse peut proposer une ressource plateforme. C’est utile quand l’utilisateur n’a pas encore de numéro, mais c’est moins personnalisé et soumis aux limites de la plateforme.

## Envoi

La page `WhatsApp` permet d’activer un mode, scanner un QR code, sauvegarder la configuration Meta, envoyer un message simple, faire un envoi groupé et déconnecter la session.

## Accord du destinataire et rythme d'envoi

Une application externe peut exiger l'accord explicite du destinataire avant de
lui écrire : MailPulse envoie d'abord la demande rédigée par l'application,
garde le contenu chiffré, puis l'envoie après un OUI ou l'annule après un NON ou
un STOP. Un destinataire qui a dit NON ou STOP ne reçoit plus rien de cette
application par ce numéro, jusqu'à un nouveau OUI. Les détails de la commande et
des événements sont dans la référence API.

Sur WhatsApp Web, ces envois passent par une file propre à chaque numéro, pour
limiter le risque de blocage :

- une pause aléatoire de 15 à 45 secondes sépare deux messages ;
- au plus 40 premières demandes d'accord par jour et par numéro ;
- aucun envoi entre 21 h et 7 h, dans le fuseau du numéro (`Africa/Abidjan` par défaut).

Ces trois réglages se changent par numéro à l'aide du script de provisionnement
(`--daily-consent-limit`, `--quiet-hours`, `--time-zone`). Les destinataires déjà
d'accord passent avant les nouvelles demandes. Meta applique ses propres limites
et n'est pas soumis à cette file.

Pour recevoir les accusés de réception et de lecture, la session Evolution doit
envoyer les évènements `MESSAGES_UPDATE` en plus de `MESSAGES_UPSERT`.

## Précautions d'envoi sur WhatsApp Web

Chaque message part après une saisie simulée, comme le ferait une personne :

- de 2 à 10 secondes selon la longueur du texte pour un message de l'API ou d'une
  application externe ;
- au plus 4 secondes pour un code de vérification, que le destinataire attend ;
- de 0,5 à 1,5 seconde pour les campagnes, les relances et les envois depuis le
  tableau de bord, qui partent les uns après les autres.

Les liens sont envoyés sans aperçu : le serveur ne va plus chercher les pages
citées.

Aucune précaution ne rend WhatsApp Web sûr pour des envois en masse à des
destinataires qui ne vous connaissent pas. Pour ce besoin, utilisez Meta Cloud API.

## Session et QR code

La page WhatsApp ne recrée la session que si le serveur WhatsApp confirme qu'elle
n'existe plus. Un serveur momentanément injoignable affiche une erreur et laisse
la session intacte : réessayez quelques instants plus tard.

Un numéro également utilisé par une application externe ne peut être ni
déconnecté ni réinitialisé depuis cette page, pour ne pas couper l'application.
