---
title: Phone verification
description: Confirm that a phone number belongs to your user with a one-time code sent on WhatsApp.
---

The verification API sends a 6-digit code on WhatsApp, then tells you whether the
code your user typed is the right one. MailPulse generates the code, sends it
through your organization's WhatsApp transport, counts attempts and handles
expiry: your application never sees the code.

Authentication is the same as `POST /api/v1/messages` (`Authorization: Bearer mp_live_xxx`).
The organization needs a working WhatsApp transport (connected Evolution
instance or configured WhatsApp Cloud API), otherwise the API answers `409`.

## Send a code

```bash
curl -X POST $MAILPULSE_URL/api/v1/verifications \
  -H "Authorization: Bearer $MAILPULSE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"channel":"whatsapp","to":"+2250700000000","locale":"en","reference":"signup_42"}'
```

`to` must be international (`+…` or `00…`). `locale` is `fr` (default) or `en`.
`reference` is optional and echoed back. Response `201`:

```json
{
  "id": "cmf8x2k0p0000abcd1234efgh",
  "status": "pending",
  "channel": "whatsapp",
  "to_masked": "+225 07 ** ** ** 00",
  "reference": "signup_42",
  "expires_at": "2026-09-23T10:10:00.000Z",
  "created_at": "2026-09-23T10:00:00.000Z",
  "approved_at": null
}
```

## Check the code

```bash
curl -X POST $MAILPULSE_URL/api/v1/verifications/cmf8x2k0p0000abcd1234efgh/check \
  -H "Authorization: Bearer $MAILPULSE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"code":"123456"}'
```

Right code: `200 {"id":"…","status":"approved"}`. Otherwise `422` with `status` and
`error`: `pending` + `code_invalide` (wrong code, retry), `max_attempts` +
`trop_de_tentatives` (5 wrong codes), `expired`, `canceled` (a newer code was sent),
`approved` (already used) or `failed` (never sent), all with `expire`.

## Read a verification

```bash
curl $MAILPULSE_URL/api/v1/verifications/cmf8x2k0p0000abcd1234efgh \
  -H "Authorization: Bearer $MAILPULSE_API_KEY"
```

Returns the current state. Another organization's verification answers `404`.

## Resend and limits

Resending is a new `POST` for the same number: the previous pending code is
canceled. Limits: 1 send per minute and 5 per hour per number and organization,
20 per hour per API key, 100 per hour per organization, and 30 per minute per
organization shared with API WhatsApp messages (same sending number). Beyond
that: `429 {"error":"trop_de_demandes","retry_after":42}` with a `Retry-After`
header.

Other errors: `409 whatsapp_indisponible`, `422 Validation failed` (a doubtful
number is reported under `field_errors.to`),
`502 envoi_echoue` (provider refused, verification stored as `failed`),
`503 verification_indisponible` (service not configured).

Codes come from a cryptographic generator, are stored only as a salted HMAC and
compared in constant time. They expire after 10 minutes, allow 5 attempts and
approve once. The code goes to the exact number only, never to a legacy variant,
and a failed send stores a classified cause (`numero_non_whatsapp`,
`delai_depasse`, `transport_erreur`), never the provider text. With WhatsApp
Cloud API, Meta only delivers free-form text inside the 24-hour window opened by
the user; prefer an Evolution instance otherwise.
